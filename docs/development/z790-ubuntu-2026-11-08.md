# Z790 Ubuntu 24.04.3 boot and installation acceptance

## Failure and scope

The affected machine is an ASUS Z790 HERO, BIOS 3107, Core i9-14900KS and
64 GiB RAM. Installation traffic used a PCIe Intel I350. The onboard I226-V
had no cable and was not accepted by this test. Secure Boot was disabled.

Ubuntu's GRUB `initrd` command failed immediately after `trying verifier tpm`.
Unloading GRUB's TPM module let the identical initrd load and boot. The fix is
an opt-in GRUB entry, not a Linux network-driver replacement. The native iPXE
bootstrap also avoids the AMI BMC USB keyboard conflict by retaining firmware
USB handling. These are separate steps of the boot path.

## Published artifact

The existing `Ubuntu/ubuntu-24.04.3-live-server-amd64.iso` was replaced in place
after confirming that no client was using the media. A rollback copy and a
transaction record were retained outside the public ISO inventory.

## Installation results

The site-specific no-USB iPXE bootstrap reached the native iVentoy menu using
the I350. Selecting the automatic script and then
`Ubuntu Server (low-memory compatibility; skips GRUB TPM measurement)` loaded
the installer, injected setup and displayed the normal filesystem/disk
selection. The authorized 480 GB internal SSD's old single-disk LVM was removed
after the partition preview and explicit confirmation.

The installation completed unattended and rebooted into its local EFI entry.
The first hard-disk boot passed these checks:

- GPT partitions: EFI 1 GiB, `/boot` 2 GiB, `/tmp` 5 GiB, swap 32 GiB,
  `/var` 64 GiB, `/` 128 GiB, and remaining `/home` approximately 215.1 GiB.
  EFI is FAT32; the selected data filesystem is ext4.
- Root console login and separate root/user password SSH logins work. Two
  root SSH sessions and one user session showed no Ventoy/setup login banner.
- I350 obtained DHCP; the installed system runs the expected GA kernel.
- Kernel image/modules are held. APT periodic refresh and unattended upgrades
  are disabled; both APT timers and `unattended-upgrades.service` are masked.
- Preloaded setup matches the published hash and has executable mode `0700`.
  Preloading is not a claim that software installation/full setup was run.
- No failed systemd units. Installation reports remain available silently on
  disk, and the generated profile/issue banner files are absent.

The virtual bootstrap CD was then detached and the installed system was
rebooted normally once more. A new boot ID, `BootCurrent: 0000` for the local
Ubuntu EFI entry, working root SSH, unchanged partitions/kernel/setup hash,
disabled updates and no failed units were verified again. This second startup
did not depend on mounted installation media.

A separate earlier manual installation on this machine completed and survived
hard-disk restarts. Its setup was upgraded to alpha58 and its SSH socket
activation/boot verification was checked before the automatic reinstall.
That manual run preceded this exact compatibility ISO; it is not a claim of
a second complete manual installation of the final artifact.

## Limits and operational use

On this affected firmware, choose the named compatibility item after the
normal iVentoy manual/automatic script selection. The unchanged default item
still uses the TPM verifier and can reproduce its allocation error. The
compatibility choice skips GRUB TPM measurements; it does not change firmware
TPM or Secure Boot settings.

This acceptance covers the stated Ubuntu GA kernel, ISO hash and Z790/I350
path. Other Ubuntu releases, HWE, CentOS/RHEL loaders, onboard I226-V traffic
and Secure Boot require their own checks. It does not establish that every
`can't allocate initrd` error has been resolved.

The private deployment evidence is retained under the center's
`nov08-grub-low-memory/publication-alpha58` directory. Raw answer files,
credentials and site-specific boot media are intentionally not committed.
