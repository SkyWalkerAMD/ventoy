# Debian 13.7 installation-media validation

Debian 13.7 uses the existing `debian-13` profile and the Trixie suite. The
shared ISO entry supports the manual installer and the PXE automatic script;
it does not need a second ISO or a separate version-specific profile.

The hash matches Debian's [DVD checksum file](https://cdimage.debian.org/debian-cd/current/amd64/iso-dvd/SHA256SUMS).

[official CD signing key](https://www.debian.org/CD/key-DA87E80D6294BE9B.txt),
fingerprint `DF9B9C49EAA9298432589D76DA87E80D6294BE9B`, checked against
[Debian's verification guidance](https://www.debian.org/CD/verify).
The `current` download directory is mutable; the media identity and content
hash above identify the specific artifact checked here.

## Shared entry and policy regression

`TestDebian137SharedInstallationEntry` exercises the management API through
entry creation, preparation, enablement, inventory reporting and issuance of
an authorized installation script. It verifies:

- The original ISO path remains the shared entry for both installation modes.
- The prepared setup bundle is copied unchanged and identified by its hash.
- The manual path receives finish-install, update-policy, installer-cache and
  diagnostics hooks, without an unconditional preseed or forced automatic
  kernel command line.
- DVD automatic installation uses local installation media, `pkgsel/upgrade
  none`, the configured account policy and the target setup-copy hook.
- The generic entry has no preauthorized destructive disk selection.

Profile tests additionally cover both Debian 13.7 DVD and netinst filenames,
while rejecting ARM64 and unsupported live-media variants. Netinst filename
acceptance is not a claim that a Debian 13.7 netinst ISO was installed in this
validation.

Manual installation continues to use the user's installer choices. Preloading
the setup executable does not mean the full setup workflow has already run.
The Debian update policy is applied during installation; the remaining setup
workflow is explicitly invoked after installation.

## Network-driver inspection

Both text and GTK installer paths were inspected. Debian's small initial
initramfs does not contain every network module: standard NIC and USB NIC
components are also supplied as installer udebs on the DVD.

| Device or module | Result |
| --- | --- |
| Intel I226-V | `igc` in the NIC udeb and installed-kernel package contains PCI alias `8086:125C`; no new driver compilation is indicated by this media audit. |
| USB Ethernet | The DVD USB NIC udeb and installed kernel contain `r8152`, `asix` and `ax88179_178a`; compatibility still depends on the adapter's actual VID/PID. |
| Intel E610 | Stock `ixgbe` lacks all five required E610 IDs: `57AE`, `57AF`, `57B0`, `57B1`, `57B2`. An exact-kernel injection is required. |

A GRUB `can't allocate initrd` error occurs before these Linux drivers run.
The module audit does not establish the cause or resolution of that firmware
boot failure.

## Exact-kernel E610 preparation

The existing r4 offline package has no module for `6.12.107+deb13-amd64`.
An additional `ixgbe` 6.4.5 module was compiled in a disposable Debian 13
copy-on-write VM with GCC 14.2, using the exact header and kbuild packages from
the verified DVD. No running deployment kernel or production ISO was changed
by this preparation.

The source archive is the existing verified E610 source, SHA-256
`8d23f2c329e0b93055236e67ffbf1de99d8dce32ccc75beb759774c7c24d7ed4`.
The resulting signed module SHA-256 is
`459aea97c901fb7f76fbf58ef24b83e145454117eb361b7e4cd4f2a09f759b60`.
Its version, exact vermagic and all five E610 PCI aliases were checked.

The following isolated checks passed:

- Three successive module load/unload cycles under the actual DVD kernel in
  a diskless QEMU guest, including the stock `dca` dependency.
- The r4 installation completion hook against a disposable Debian target,
  including `depmod` precedence, `update-initramfs`, and the offline verifier.
- The installed target's generated initramfs contains
  `updates/e610/ixgbe.ko` for the exact kernel.
- Separate text and GTK boot trees can generate their own module indexes;
  the shared injection archive contains the E610 module, dependency and
  installation completion hook.

The public enrollment certificate accompanies the signed module. Signing does
not by itself authorize the module under a machine's Secure Boot policy.
Physical E610 networking, Secure Boot enrollment, full installation and normal
reboots remain hardware acceptance checks; the isolated results must not be
reported as those tests passing.

A separate complete ISO candidate was built with SHA-256
`221bd66e559cdfd48b744e22ba3f013593cbabbdc322c3ec6d281f33ef9fc93d`.
Both installer paths contain the exact E610 driver and the current
`0.3.0-alpha.57` setup preload, SHA-256
`69f574fb2559bb1d79e7003fbbb1ae6e384c4a762f6924b86379ce50910723b9`.
The text and GTK initramfs were read back and verified, including the updated
quiet login-report hooks. Their compressed sizes are 71,771,467 and
124,125,993 bytes respectively. The setup is stored as installer data; the
finish-install hook publishes it in the installed root with executable mode
`0700`.

The BIOS/UEFI boot metadata and original boot kernel were retained. Existing
Debian preseed contents were unchanged, so the shared ISO does not itself
force automatic installation. The original ISO hash remained unchanged.
If a driver archive is registered for the baked ISO, its manifest size and
modification time must refer to the newly published artifact rather than the
original DVD.

## Validation boundary

The focused Go regression tests passed. The source-media audit, module ABI
test and target-initramfs persistence test passed. These results prepare the
Debian 13.7 entry for controlled publication; they do not imply publication
or a physical installation has already completed.
